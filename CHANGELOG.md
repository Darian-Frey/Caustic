## [Unreleased]

### Added

- Phase 8 — animation system: new `caustic::anim` namespace with `Envelope` variant (`Static`/`Linear`/`Sine`) in `core/include/caustic/envelope.hpp`, flat `Target` enum + `write_target` dispatch in `core/include/caustic/animation.hpp` covering 16 animatable parameters (modular `k`, hypotrochoid `d`, epitrochoid `d`, Lissajous `phi`/`A`/`B`, phyllotaxis `alpha`/`k`, polygon chord `k`/`rotation`, per-layer `rotate`/`scale`/`translateX`/`translateY`, camera `zoom`). `AnimationSpec` on `AppState` carries target + envelope + duration + bake count + playback state. App gains an Animation panel: target combo, envelope type combo with per-type params, duration slider, play/pause + reset, time scrub, frame count, name prefix, and a "Bake SVG sequence" button that writes numbered frames to `$XDG_CONFIG_HOME/caustic/animations/`. Per-frame loop ticks the spec, evaluates the envelope at `t`, writes the target field, and dirties the canvas. 114 doctest cases passing (102 → 114; 12 new in `test_envelope.cpp` covering envelope evaluation, `write_target` dispatch, tick play/pause/wrap, plus the ROADMAP acceptance — Linear(2→3) over 60 frames). Deferred: `Keyframed` envelope (would need a 2D curve-editor widget) and preset-borne animation (current `AnimationSpec` is editor-only; serialising it would bump the preset schema again).
- Initial documentation scaffolding: `README.md`, `CLAUDE.md`, `ROADMAP.md`, `ARCHITECTURE.md`, `SPEC.md`, `BUILD.md`, `CHANGELOG.md`.
- Architecture decisions locked: Caustic name selected; rlImGui chosen as GUI layer; v1 generator set fixed at modular chord, hypotrochoid, epitrochoid, Lissajous; on-demand rendering model defined.
- v1.1 generator roadmap expanded: superformula and phyllotaxis added to Phase 9 (parametric curve expansion); strange attractors (Clifford, de Jong, Tinkerbell) added as new Phase 10 with a dedicated iterative-orbit pipeline tier; Polish & release moved to Phase 11. L-systems and tilings considered and explicitly rejected.
- Phase 0 scaffolding landed: CMake workspace with `core/`, `render/`, `app/`, `cli/`, `tests/`; `core/include/caustic/vec2.hpp` + 3 doctest cases (all passing); `app/main.cpp` 1280×800 black window with one ImGui panel; `cli/main.cpp` prints `caustic 0.1.0`; `.gitignore` and `.editorconfig`. Dependency matrix pinned: raylib 6.0, rlImGui `Raylib_6_0`, Dear ImGui v1.92.7, nlohmann/json v3.11.3, doctest v2.4.11. `cmake --build build` succeeds; `ctest --test-dir build` is green.
- Phase 1 — modular chord MVP: `ParametricCurve` interface, `Circle`, `Chord`/`ChordSet`, `modular_chord(N, k)` generator, `RaylibRenderer` with cached `RenderTexture2D` and dirty-flag rendering loop. App displays cardioid (N=200, k=2). Idle CPU near-zero when not interacting.
- Phase 2 — roulettes + Lissajous: `HypotrochoidCurve`, `EpitrochoidCurve`, `LissajousCurve` (each a `ParametricCurve` impl); `sample_curve()` polyline sampler; `GeometryBuffer` (polylines + chords union per architecture §4.1); renderer accepts `GeometryBuffer` with fit-to-content scaling; app cycles all four generators via keys 1–4. Period computed from `gcd(R, r)` for trochoids and `gcd(a, b)` for Lissajous; non-integer ratios fall back gracefully (curve will not perfectly close, per architecture §4.2 caveat). 26 doctest cases passing.
- Phase 3 — style system: `Color` (RGBA doubles), `ColorMap` interface + `Solid`/`LinearGradient`/`HsvSweep`/`Diverging` impls, `Indexer` enum (`ChordIndex`, `ChordLength`, `Angle`, `CurveT`), `StrokeStyle` (width_min/max, indexer, opacity), `Style` bundle, background colour. Renderer applies per-segment color and width via the chosen indexer + colormap and uses raylib's `DrawLineEx` for variable stroke widths. Out-of-spec polish: `Style.cyclic` flag triangle-wave-remaps t (1 - |2t - 1|) so closed-curve colormaps and widths return to their starting value at t=1, hiding the wrap-around seam (opt-in per Style; default off). 42 doctest cases passing. Note: `caustic::Color` shadows raylib's `::Color` inside the `caustic` namespace, so raylib calls in render code that need the WHITE/BLACK macros now construct `::Color{...}` literals explicitly.
- Phase 4 — rlImGui UI: app refactored around an `AppState` struct (per-generator params, style spec, camera). `core/include/caustic/camera.hpp` introduces `CameraState` (pan in screen pixels, zoom multiplier on top of fit-to-content). Renderer signature gains `CameraState`. Two ImGui windows: parameters panel (generator combo + param sliders with scroll-wheel-on-hover, Shift ×10 / Ctrl ×0.1 modifiers per CLAUDE.md convention) and style panel (colormap type + per-type controls + indexer + stroke + opacity + background + cyclic checkbox). Coarse drag-time preview gated on `ImGui::IsAnyItemActive()` — modular chord N ÷ 4, polyline samples ÷ 2; full-quality redraw ~1 frame after slider release. Camera: middle-click pan, cursor-relative scroll-zoom (clamped to [0.1, 100]), F or 0 resets. Keys 1–4 retained as power-user generator shortcuts. Deviation from architecture: R/r and a/b sliders restricted to integers — non-integer ratios produce non-closing curves that look broken at default sample density; the architecture's "drag Lissajous a/b through irrational values to watch precession" demo is unavailable until a future sample-over-many-revolutions toggle is added.
- Roadmap expanded with **Phase 10 — String-art expansion** (v1.1): `PolygonCurve` and `LinearEnvelope` generators for the classical curve-stitching pattern family that gave Caustic its name (chord envelopes are the optical caustics of converging straight lines). Polygon-vertex modular chords (deltoid, hexagram, etc.) and parabolic corner-fan envelopes (the "thread and nails" patterns) are the visible deliverables. Strange attractors renumbered Phase 11; Polish & release renumbered Phase 12. ARCHITECTURE.md §1 aspirational list, §4.2 generators, §10 phased plan, §11 resolved decisions item 4, and §12 risks all updated.
- Phase 10 — string-art expansion: `PolygonCurve` as a new `ParametricCurve` along a regular n-gon's perimeter (constant arc-length parametrisation, vertices on the unit circle). `polygon_chord(n_sides, N, k, rotation_rad)` applies the modular chord rule to N points along that perimeter — deltoid envelope falls out at n=3, k=2; hexagram at n=6, k=2; etc. `linear_envelope(a_start, a_end, b_start, b_end, N, k)` chord set between two line segments — classical schoolchild "thread and nails" pattern. Perpendicular segments + k=1 = parabolic corner fan; parallel segments + k=-1 = bowtie. `GeneratorType` gains `PolygonChord` and `LinearEnvelope` values; `GeneratorSpec` gains `PolygonChordParams` and `LinearEnvelopeParams` (the latter holds four `Vec2` endpoints). JSON ser/deser handles both; factory dispatches them. App UI: sliders for n-sides/N/k/rotation; `SliderFloat2` widgets for line endpoints. 6 bundled presets shipped — `corner_fan`, `envelope_bowtie`, `deltoid`, `hexagram`, plus two multi-layer compositions (`four_bowties` and `rgb_triangle`) that exercise Phase 9 Stage A's scene-with-layers infrastructure. 102 doctest cases passing (88 → 102; 8 new polygon + 6 new linear-envelope), 20/20 CTest CLI smoke (14 → 20). Hybrid-mode generator + Maurer rose remain deferred — the concrete chord-set special cases cover the user-visible patterns without needing nested-generator JSON.
- Phase 9 Stage A landed — multi-layer scene infrastructure + per-layer transforms + array tools. `caustic::Preset` now wraps a `caustic::Scene` containing an ordered list of `caustic::Layer { GeneratorSpec, StyleSpec, LayerTransform, visible }`. Preset version bumped to 2; v1 presets auto-promote on load (`style.background` migrates to `scene.background`, the top-level generator+style become a single layer with identity transform). All 5 bundled presets migrated to on-disk v2 format. `LayerTransform { translate, rotate_rad, scale, mirror_x, mirror_y }` applied in Mirror → Scale → Rotate → Translate order. New `caustic/scene_render.hpp` exposes `LayerRender` (geometry + style + name) and `build_renderables(Scene, coarse)`; both renderers accept `vector<LayerRender>` + background and emit one `<g>` per layer in SVG. New `caustic/array_tools.hpp` provides `rotational_array`, `grid_tile`, `mirror_reflect` (free functions returning vectors of derived layers). App gains a Layers panel with add / duplicate / remove / move / visibility / per-layer transform sliders / array tool Apply buttons. SPEC.md §3 schema updated to v2. 74 doctest cases passing (66 → 74 with array tool + multi-layer additions), 11/11 CTest CLI smoke. Both full and headless builds clean.
- ROADMAP Phase 9 amended with per-layer transforms (translate/rotate/scale/mirror) and array tools (rotational, grid, mirror-reflect). Triggered by the user's second image-set review — the symmetric and tiled string-art compositions can't be authored ergonomically with just multi-layer scenes; you need at least rotational-array and grid-tile to avoid placing every motif manually. Phase 9 now structured in two stages: A = Scene/Layer infrastructure + transforms + array tools (the load-bearing dependency for the rest), B = the original curve content (rose, Maurer rose, superformula, phyllotaxis, hybrid mode). Preset version will bump to 2 with v1→v2 auto-promote on load. ARCHITECTURE.md §1 aspirational list, §4.2 generators (new multi-layer subsection), and §10 phased plan all updated.
- Phase 7 — CLI tool: `caustic-cli preset.json -o out.svg` with `--width`/`--height`/`--margin`/`--plotter`/`--simplify` flags and SPEC.md §5 exit codes (0 success / 1 bad-args / 2 file-not-found / 3 validation-failed / 4 write-failed). Links only `caustic::core` + `caustic::render-svg`; the architectural invariant is enforced by `.github/workflows/ci.yml`'s headless job, which configures with `CAUSTIC_BUILD_APP=OFF` and fails if any `libraylib*` artifact appears in the build tree. CTest now has 10 CLI smoke tests (version/help, missing-args, file-not-found, per-preset render for all 5 bundled presets, plotter-mode render) on top of the 64 doctest cases. Local batch render of all bundled presets clocks 48 ms wall (vs the 30 s ROADMAP target). Shared spec→runtime factories landed in `core/include/caustic/{geometry,style}_factory.hpp`; app and CLI both consume them, removing the previous duplication. **v1 functional milestone:** Phases 0–7 close out the v1 scope (four generators + style + UI + presets + SVG + CLI). Phases 8–11 are user-prioritized v1.1 expansions; Phase 12 is the path to public 1.0.
- Phase 6 — SVG export: `render/svg_renderer.{hpp,cpp}` introduces `caustic::SvgOptions` + `render_svg()` + `write_svg()`. `render/CMakeLists.txt` split into `caustic-render-svg` (always built, no raylib — verified by headless build with `CAUSTIC_BUILD_APP=OFF`) and `caustic-render-raylib` (only when GUI is built). Output: XML preamble, `<svg>` with `viewBox="0 0 W H"`, fit-to-content scaling with configurable margin (default 5%), math-up world coords flipped to SVG screen-down at emission time, fixed 6-decimal precision throughout. Coloured mode: per-segment `<line>` for chords and polylines (preserves colormap gradients). Plotter mode: no background rect, no `stroke-opacity`, single colour (default `#000000`), chord set sorted by start point lexicographically, polylines emitted as single `<polyline>` for one pen-down per curve. Determinism: byte-identical output across runs (doctest). Export button in the Presets panel writes to `$XDG_CONFIG_HOME/caustic/exports/`. Discoverability hints added to both parameter and style panels (Ctrl+click on sliders to type, click colour squares for hex/RGB/HSV picker, scroll-wheel modifier table). Deferred: Douglas–Peucker simplification (`SvgOptions::simplify_epsilon` plumbed but not applied); true nearest-neighbour pen-travel reorder for plotter mode (current sort is lexicographic). 64 doctest cases passing.
- Phase 5 — preset system: `caustic::Preset` (with `GeneratorSpec`, `StyleSpec`, and `CameraState`) in `core/include/caustic/preset.hpp` plus `preset_io.hpp` providing `to_json`/`from_json` ADL hooks, `save_preset`/`load_preset` (atomic write to file), and `user_preset_dir()` (respects `$XDG_CONFIG_HOME`, falls back to `$HOME/.config/caustic/presets`). `caustic-core` now publicly links `nlohmann_json::nlohmann_json`. App refactored: `AppState` wraps a `caustic::Preset` plus UI flags; a third ImGui panel exposes Save + Bundled/User preset lists. Five bundled presets in `presets/` cover all four generators. SPEC.md updated: camera schema changed from `{centre, zoom}` to `{pan_x_px, pan_y_px, zoom}` to match the Phase 4 implementation; `style.cyclic` field documented. Cross-canvas preset portability is therefore weak (pan is in window pixels, not world coords) — flagged as a future cleanup. Out-of-spec polish: F11 toggles borderless fullscreen via `ToggleBorderlessWindowed`; the window is resizable with a 640×400 minimum and the renderer reallocates its offscreen `RenderTexture2D` to match so the figure renders at native resolution at every size. 54 doctest cases passing (12 new for preset I/O + XDG + on-disk round-trip + bundled-preset smoke parse).

## [Unreleased]

### Added

- **IDE-style three-pane layout (2026-05-18)** — the five floating ImGui windows collapse into two draggable sidebars + a centered canvas. **Left sidebar**: Parameters + Style as tabs. **Right sidebar**: Layers + Presets + Animation as tabs. Both sidebars draggable via thin splitter strips between sidebar and canvas; widths clamped to `[180, window_w * 0.45]` so the canvas can't collapse. New `AppState::left_panel_width` / `right_panel_width` (default 320px each). Splitter cursor switches to `ImGuiMouseCursor_ResizeEW` on hover; `draw_v_splitter` helper for the left, mirror-inlined for the right (drag-right shrinks instead of grows). Five panel renderers renamed to `*_content` and stripped of their outer `ImGui::Begin/End`; `render_left_sidebar` / `render_right_sidebar` own the windows + tab bars. Canvas region: `RaylibRenderer::blit_to_screen(int x_offset = 0, int y_offset = 0)` (default args keep callers unchanged) plus new `width()`/`height()` accessors so the bake functions can save/restore canvas size. `draw_grid_overlay` signature swapped from `(screen_w, screen_h)` to `(canvas_x, canvas_y, canvas_w, canvas_h)` so grid lines clip to the canvas rectangle. Every `GetScreenWidth()/2` and `GetScreenHeight()/2` site became `canvas_cx`/`canvas_cy`. Clear-background tinted to `#121216` so the splitter strips read as a subtle dark seam rather than pure black. Sidebar text: `PushTextWrapPos(0)` inside each sidebar window so `TextDisabled` hint blocks wrap to the panel edge instead of disappearing past the right; long button labels shortened (buttons clip rather than wrap) and long checkbox labels split into checkbox + companion `TextDisabled` on the same line. Export-anywhere by default: the Export-SVG button and Ctrl+E now both open the native file picker (was: quick-save to XDG dir). Quiet startup: `SetTraceLogLevel(LOG_WARNING)` before `InitWindow` silences raylib's boot-time `INFO:` chatter while preserving warnings and errors. 33/33 CTest cases still pass.

- **AppImage packaging + bundled-preset path resolution (2026-05-18)** — `app/main.cpp` gains `executable_dir()` (via `/proc/self/exe`) and `find_bundled_preset_dir()` which tries `./presets`, then `<exe>/../share/caustic/presets`, then `<exe>/presets`, picking the first that exists. Dev runs from the repo root continue to work; installed binaries (AppImage, system install) find their presets via the share path. New `packaging/appimage/` directory holds `AppRun` (env-prep + exec shim), `caustic.desktop` (Freedesktop entry, Graphics/2DGraphics/VectorGraphics categories), `caustic.svg` (256×256 cardioid icon — 24-chord modular-chord with k=2, the canonical Caustic demo), and `build-appimage.sh` (cmake Release build → AppDir layout → linuxdeploy lib bundle → appimagetool pack → `Caustic-x86_64.AppImage`). `packaging/appimage/README.md` walks through `linuxdeploy` + `appimagetool` install, the build, bundled-preset path resolution, and troubleshooting (libfuse2, Mesa conflicts, optional ffmpeg). `.gitignore` excludes `Caustic-*.AppImage` and `Caustic.AppDir/`. Doc-side: README, MANUAL, CHANGELOG, ROADMAP refreshed to reflect the 17-generator / 27-preset state plus all the v1.1 polish work that had landed but wasn't documented.

- v1.1 polish (nice-to-have batch, 2026-05-18): five overdue ergonomics features. **Keyboard shortcuts** — `Ctrl+S` quick-save, `Ctrl+Shift+S` save-as (native dialog), `Ctrl+O` open (native dialog), `Ctrl+E` quick-export-SVG, `Ctrl+Shift+E` export-as, `Ctrl+N` new preset; the preset panel's save/open/export logic was extracted to free functions (`quick_save_preset`, `save_as_preset`, `open_preset_dialog`, `quick_export_svg`, `export_as_svg`, `reset_preset_to_default`) shared by the panel and the shortcuts. Suppressed while ImGui has a text field focused. **Polar grid mode** — new `caustic::EditorGridMode { Rectangular, Polar }` enum and `caustic::EditorGrid { mode, spacing, polar_spokes, visible, snap }` struct in `preset.hpp`. Rectangular = axis-aligned lines; Polar = concentric rings + N radial spokes. Single `draw_grid_overlay` helper renders both modes in the CustomChord and LinearEnvelope canvas overlays; `snap_world_point` snaps to nearest spacing-multiple (rectangular) or nearest ring + spoke angle (polar). **`EditorGrid` is now part of `Preset`** and round-trips through the JSON via a new `editor_grid` block (with default-fallback for older bundled presets), so a CustomChord pattern built against a specific grid keeps that grid on reload — fixes the "new nails won't line up with the saved ones" problem. **Per-chord stroke width and opacity overrides** — `GeometryBuffer.chord_width_overrides` and `chord_opacity_overrides` arrays mirror the existing `chord_color_overrides` pattern (empty = use layer style; sized-to-match = override per chord). `CustomChordParams` gains `chord_widths` and `chord_opacities`; the factory copies them through when sizes match. Both renderers consume them (`raylib_renderer.cpp` and `svg_renderer.cpp`). UI: active-width / active-opacity sliders plus Apply-to-all / Apply-to-selected / Clear-overrides buttons in the CustomChord panel. **Preset browser thumbnails** — new `ThumbnailCache` lazily renders each bundled / user preset into a 96×96 `Texture2D` via a dedicated small `RaylibRenderer`; `rlImGuiImageSize` draws each beside its name in the Presets panel. Saves invalidate the cached thumbnail for that path. **Universal pan** — left-drag now pans in every mode: middle-click drag and **Spacebar + left-drag** are universal; plain left-drag pans on most generators, on LinearEnvelope when the press misses all 4 handles, and inside CustomChord AddChord/MoveNail/RecolourChord when the press misses its target. Implemented via `state.left_drag_pan` flag set on press by the editor hit-tests; cleared on release. AddNail and Select preserve their established empty-space affordances (place / rubber-band); Spacebar+drag is the escape hatch. 159 doctest cases passing (added round-trip coverage for `editor_grid` including legacy presets without the block, plus tests for `chord_widths` / `chord_opacities`). 33 CTest CLI smoke cases unchanged.

- v1.1 Phase 9 Stage B closeout — three concrete chord-pattern generators chosen over a hybrid-mode schema refactor: **Maurer rose** (`maurer_rose(n, step_deg, samples)` — sin(n·θ) sampled at coprime step, dense fractal "necklace" pattern), **Lissajous chord** (modular chord rule on N nails sampled from a Lissajous curve), and **Superformula chord** (modular chord rule on N nails sampled from a Gielis curve). Each gets a new generator header (`generators/maurer_rose.hpp`, `lissajous_chord.hpp`, `superformula_chord.hpp`), `GeneratorType` enum entry, params struct, JSON ser/deser, factory dispatch, parameter-panel sliders, and a bundled preset (`maurer_rose_classic`, `lissajous_chord_classic`, `superformula_chord_starfish`). Generator count 14 → 17. 156 doctest cases (was 150; +6 in new `test_hybrids.cpp`: closure / bad-input / t_along monotonicity / m=0 circle special case). 33 CTest cases (was 30). Closes the Phase 9 Stage B deferred item — full hybrid-mode generator (nested-`ParametricCurve` JSON refactor) stays out of scope.

- v1.1 polish batch — four backlog items closed in one commit. **Points/scatter geometry tier for attractors**: new `GeometryBuffer.points` vector parallel to polylines and chords; new `AttractorRenderMode { Polyline, Scatter, Both }` enum on each attractor params struct; factory dispatches to either or both; raylib renderer draws `DrawCircleV` per point (radius from `stroke.width_min × 0.5` floored at 0.5px), SVG renderer emits `<circle>` per point. Bundled attractor presets switched to Scatter mode at ~1.5px / opacity 0.45 for the canonical scatter-plot look. **LinearEnvelope canvas-drag editor**: the four endpoints (a0, a1, b0, b1) render as draggable handles on the canvas; left-click + drag repositions. Handle-to-handle snap (any handle within hit radius of another snaps to that handle's exact position) lets the user rejoin split apexes (corner_fan's a_start / b_start) without pixel-hunting; snap target gets a yellow ring. Honours the same grid + snap state as the CustomChord editor. Undo/redo via Ctrl+Z / Ctrl+Y with a 50-deep `lenv_undo_stack`. **`Keyframed` envelope**: new variant in `caustic::anim::Envelope` holding `vector<pair<double, double>>` of (t, value) keys with linear interpolation between adjacent keys and edge clamping outside the first/last. UI is a table-of-rows editor in the Animation panel (add row / remove row / per-row t and value sliders). 6 new test cases in `test_envelope.cpp`. **PNG / GIF / mp4 bake**: `RaylibRenderer::write_png(path)` and `read_rgba_frame(out, w, h)` expose the offscreen canvas. Animation panel gets two new bake outputs alongside the SVG sequence — PNG sequence (with optional "encode mp4 after PNG" that shells out to `ffmpeg -c:v libx264 -pix_fmt yuv420p` on PATH), and in-process GIF encoding via single-header `msf_gif` (`MSF_GIF_IMPL` defined in `app/main.cpp`, max bit depth 16). All bakes write into `$XDG_CONFIG_HOME/caustic/animations/<name>/`. `msf_gif` and `tinyfiledialogs` added to the CMake FetchContent matrix (CMake project langs changed to `C CXX` so the C `tinyfiledialogs.c` compiles).

- **CustomChord editor punch list** — the click-to-place editor matured into a full authoring environment. Six edit modes via radio buttons: **Off** (no edit; left-click pans), **AddNail** (left-click drops a nail), **AddChord** (two clicks connect; new chord adopts the active start/end colour), **MoveNail** (click + hold on a nail, drag to reposition with snap honoured), **RecolourChord** (click on an existing chord to apply active start/end colours), **Select** (click an item to select; Shift+click toggles; drag empty space for rubber-band area-select; Delete removes). **Right-click is mode-independent** — erases the nail or chord under the cursor (nails take priority). **Undo/redo**: 50-deep snapshot-based `nail_undo_stack` / `nail_redo_stack` per generator type, cleared on layer/generator switch. Ctrl+Z / Ctrl+Y (or Ctrl+Shift+Z). **Per-chord colour and gradient**: `CustomChordParams.chord_colors` and `chord_end_colors` arrays; equal start/end = solid colour, different = renderer subdivides into 16 sub-segments with lerped colour. **AddChord preview line**: while the user has clicked the first nail and is choosing the second, a live gradient line draws from that nail to the cursor. **Selection summary** with "Delete selected" and "Recolour selected" buttons. **Native file dialogs** via tinyfiledialogs for save-anywhere / open-anywhere / export-anywhere. **Grid overlay + snap-to-grid** in the editor with adjustable spacing and a "show pin numbers" toggle. **Left-click drag pan** (when edit mode = off). Bundled preset `custom_starburst.json` ships as an authored example.

- **DiamondStack generator** — 13th generator: stacked hourglass / diamond modules with parabolic chord fans at each tip. Adjacent modules share tip points, producing the pinched-waist silhouette. Parameters: `n_modules`, `N` (strings per fan), `aspect` (`half_waist / half_module_height`), `rotation_rad`, **`fans`** enum `DiamondStackFans { Both, Vertical, Horizontal }`. Vertical = top + bottom apexes (fills top/bottom triangles); Horizontal = left + right (fills the left/right triangles); Both = all 4 fans per module. The vertical/horizontal split is the standard recipe for two-colour stacked-diamond compositions — one layer per fan set, each independently styled. Bundled presets: `diamond_stack_classic`, `diamond_stack_two_colour` (the two-colour recipe), `diamond_star_neon` (Diamond + Rotational array N=4), `square_grid_2x3` (grid-tile array). Animation `Target` enum gains `DiamondStack_aspect` and `DiamondStack_rotation`. Unit tests in `test_diamond_stack.cpp`.

- **MANUAL.md** — task-oriented user guide added: the interface, the generators, style, camera, layers, presets, SVG export, animation, headless CLI, recipes (parabolic corner fan, bowtie, hourglass, diamond unit, hexagram, cardioid/nephroid/times tables, spirograph, attractor portrait, sunflower), and common pitfalls. Provides the practical "how do I make X" complement to ARCHITECTURE.md / SPEC.md / ROADMAP.md.

- **LinearEnvelope preset gallery rework (k=−1)** — discovered that the "string art" look requires the reversed-index pattern: with two segments sharing an apex, `k = +1` produces parallel chord lines filling a wedge (looks like a filled triangle), while `k = −1` produces the canonical **parabolic envelope** (chord lines tangent to a parabola — the curved string-art shape). All bundled LinearEnvelope presets reworked to use k=−1 with shared-apex segments; new presets `swoop_pair` (hourglass / opposing parabolas) and `bowtie_hourglass` (two stacked bowties) demonstrate the recipe. Documented in MANUAL.md's LinearEnvelope table as the single most important parameter in Caustic for the string-art family.

- Phase 11 — strange attractors: `core/include/caustic/generators/attractors.hpp` introduces a generic `iterate_orbit<Step>` template (burn-in + divergence detection: `|x|` or `|y| > 1e6` or non-finite truncates the orbit and sets `AttractorOrbit.diverged`) and three step functions: `clifford_orbit`, `de_jong_orbit`, `tinkerbell_orbit`. New `GeneratorType::Clifford`, `DeJong`, `Tinkerbell` values with per-attractor parameter blocks (each holds `a, b, c, d, x0, y0, iterations, burn_in` — canonical defaults per attractor) flow through preset JSON ser/deser, the geometry factory (coarse preview tier divides iterations ÷ 4, floor 500), the parameter panel (Reset buttons surface each struct's defaults), and the animation `Target` enum (12 new entries — a/b/c/d for each attractor — so envelopes can sweep coefficients). Polyline-render path used; orbit chronology is colour-encoded via the existing `CurveT` indexer (i/(N-1) on the polyline is the iteration index). Three bundled presets ship with styling tuned for orbital-density readability (width 0.15–0.2, opacity 0.10–0.25, iterations 20k–80k): `clifford_butterfly`, `de_jong_classic`, `tinkerbell`. 123 doctest cases passing (114 → 123: +9 attractor cases covering bounded-orbit / divergence / determinism / burn-in / zero-iterations / custom-step). 23 CTest CLI smoke cases (20 → 23). Deferred: points/scatter geometry tier — strange attractors are conventionally rendered as one dot per iterate, not connected; would need `GeometryBuffer.points` plus renderer support (~150 lines). v1.1 generator set is now complete at 12 generators across three pipeline tiers.

Per-frame loop ticks the spec, evaluates the envelope at `t`, writes the target field, and dirties the canvas. 114 doctest cases passing (102 → 114; 12 new in `test_envelope.cpp` covering envelope evaluation, `write_target` dispatch, tick play/pause/wrap, plus the ROADMAP acceptance — Linear(2→3) over 60 frames). - Roadmap expanded with **Phase 10 — String-art expansion** (v1.1): `PolygonCurve` and `LinearEnvelope` generators for the classical curve-stitching pattern family that gave Caustic its name (chord envelopes are the optical caustics of converging straight lines). - Phase 10 — string-art expansion: `PolygonCurve` as a new `ParametricCurve` along a regular n-gon's perimeter (constant arc-length parametrisation, vertices on the unit circle). `polygon_chord(n_sides, N, k, rotation_rad)` applies the modular chord rule to N points along that perimeter — deltoid envelope falls out at n=3, k=2; hexagram at n=6, k=2; etc. `linear_envelope(a_start, a_end, b_start, b_end, N, k)` chord set between two line segments — classical schoolchild "thread and nails" pattern. Perpendicular segments + k=1 = parabolic corner fan; parallel segments + k=-1 = bowtie. `GeneratorType` gains `PolygonChord` and `LinearEnvelope` values; `GeneratorSpec` gains `PolygonChordParams` and `LinearEnvelopeParams` (the latter holds four `Vec2` endpoints). JSON ser/deser handles both; factory dispatches them. New `caustic/array_tools.hpp` provides `rotational_array`, `grid_tile`, `mirror_reflect` (free functions returning vectors of derived layers). App gains a Layers panel with add / duplicate / remove / move / visibility / per-layer transform sliders / array tool Apply buttons. SPEC.md §3 schema updated to v2. 74 doctest cases passing (66 → 74 with array tool + multi-layer additions), 11/11 CTest CLI smoke. Both full and headless builds clean.
